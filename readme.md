# Buff

Buff - небольшой типизированный язык с простым синтаксисом, который компилируется в C99.

Цель проекта: дать удобный синтаксис уровня простых современных языков, сохранить скорость и контроль C, но убрать часть его лишней церемонии.

Важно: текущая версия уже имеет настоящий frontend с lexer, parser, AST и semantic analysis, но Buff пока остается развивающимся языком. Это не готовая замена Rust или C++.

## Быстрый старт

Для генерации C-кода:

```text
lua buffc.lua main.buff -o main.c --no-compile
```

Для генерации и компиляции через GCC:

```text
lua buffc.lua main.buff -o main.c -c
```

Для генерации, компиляции и запуска:

```text
lua buffc.lua main.buff -o main.c -r
```

Дополнительный компилятор C можно указать так:

```text
lua buffc.lua main.buff -o main.c -c --cc clang
```

По умолчанию используется:

```text
gcc -std=c99 -Wall -Wextra -O2
```

Если C-компилятор не установлен, Buff все равно может успешно сгенерировать `.c`-файл с параметром `--no-compile`.

## Как работает Buff сейчас

Компиляция проходит через несколько этапов:

```text
.buff files
    |
    v
recursive imports
    |
    v
lexer: text -> tokens
    |
    v
recursive descent parser: tokens -> AST
    |
    v
semantic analysis: names, types, scopes
    |
    v
C99 backend: AST -> .c
    |
    v
optional C compiler and executable
```

### 1. Импорты

Buff-файлы можно подключать относительно текущего файла:

```buff
import "player.buff"
import "<stdio.h>"
```

`.buff`-импорты рекурсивно загружаются до разбора. Пути нормализуются, поэтому варианты `player.buff` и `./player.buff` не создают две копии одного модуля. Циклические импорты завершаются диагностикой.

C-заголовки передаются в сгенерированный файл:

```c
#include <stdio.h>
```

Сейчас импорт - это сборка исходников в единый контекст. Системы публичных модулей, приватных символов и package manager пока нет.

### 2. Lexer

Lexer читает исходник посимвольно и создает токены. Каждый токен содержит:

- тип;
- значение;
- имя файла;
- строку;
- колонку.

Благодаря этому ошибки выглядят так:

```text
main.buff:3:5: unknown type 'MissingType'
```

Поддерживаются идентификаторы, числа, строки, ключевые слова, комментарии, операторы и скобки.

### 3. Parser и AST

Parser использует рекурсивный спуск. Для выражений используется Pratt-подобный алгоритм с приоритетами операторов.

Например:

```buff
let result: int = 2 + 3 * 4
```

разбирается как дерево, где умножение находится глубже сложения. Поэтому вложенные выражения обрабатываются правильно, а не заменяются регулярными выражениями.

### 4. Semantic analysis

Перед генерацией C Buff проверяет:

- существование типов;
- существование функций и переменных;
- повторное объявление переменных;
- количество аргументов функций;
- совместимость типов;
- допустимость присваивания;
- допустимость унарных операторов;
- допустимые типы для `match`;
- циклические импорты.

Ошибки останавливают компиляцию до создания `.c`-файла.

### 5. Backend

Backend генерирует C99 из AST. Он автоматически создает:

- стандартные include;
- структуры;
- прототипы функций;
- константы;
- тела функций;
- выражения и управляющие конструкции.

Порядок функций в Buff не обязан совпадать с порядком вызовов, потому что прототипы создаются заранее.

## Синтаксис Buff сейчас

### Функции

```buff
fn add(a: int, b: int) -> int
    return a + b
end

fn log_message(message: string)
    println(message)
end
```

Если возвращаемый тип не указан, используется `void`.

### Структуры

```buff
struct Player
    hp: int
    speed: float
end
```

### Переменные

```buff
let health: int = 100
var speed: float = 4.5
let title: string = "Player"
```

Тип можно указывать явно. Простые значения также могут выводиться из выражения.

### Указатели и поля

```buff
fn damage(player: Player*, amount: int)
    player.hp = player.hp - amount
end
```

Для указателя `player.hp` генерируется как `player->hp`.

### Условия

```buff
if health > 0 then
    println("alive")
elseif health == 0 then
    println("dead")
else
    println("invalid")
end
```

### Циклы

```buff
while health > 0 do
    health = health - 1
end

for index = 0, 10 do
    println(index)
end
```

### Match

`match` сейчас предназначен для `int`, `char` и `bool`:

```buff
match status
    case 0
        println("idle")
    case 1
        println("running")
    default
        println("unknown")
end
```

В C это генерируется как `switch`.

### Память и Arena

```buff
fn main() -> int
    let hero: Player* = spawn Player in game_arena
    hero.hp = 100
    return 0
end
```

Runtime находится в [buff_runtime.h](buff_runtime.h). Он содержит:

- `Arena`;
- `arena_make`;
- `arena_alloc`;
- `arena_free`;
- глобальную `game_arena` с ленивой инициализацией.

Выделения выровнены по 8 байтам. Есть проверки переполнения размера и выхода за пределы арены.

### Печать

Одиночные значения печатаются с учетом типа:

```buff
println(42)       -- printf("%d", 42)
println(4.5)      -- printf("%f", 4.5)
println("hello")  -- printf("%s", "hello")
println(true)     -- printf("%s", "true")
```

Форматная форма тоже поддерживается:

```buff
println("HP: %d", hero.hp)
```

## Что уже есть

- Lexer с координатами ошибок.
- Parser и AST.
- Рекурсивные импорты `.buff`.
- Обнаружение циклических импортов.
- Типы `int`, `float`, `double`, `char`, `bool`, `string`, `void` и указатели.
- `struct`.
- Функции и прототипы.
- Переменные и присваивания.
- Арифметика и сравнения.
- `if`, `elseif`, `else`.
- `while` и числовой `for`.
- `match` для целых, символов и bool.
- `spawn` через Arena runtime.
- `print` и `println`.
- Генерация C99.
- Подробные ошибки с файлом, строкой и колонкой.
- CLI-флаги `-o`, `-c`, `-r`, `--cc`, `--no-compile`.

## Что пока ограничено

- Нет полноценной стандартной библиотеки Buff.
- Нет package manager.
- Нет namespace и приватных символов модулей.
- Нет generics.
- Нет enum и pattern matching по сложным типам.
- Нет нормального `string` runtime с длиной и безопасными операциями.
- Нет автоматического управления памятью.
- Указатели остаются небезопасными, как в C.
- Нет borrow checker и ownership-модели Rust.
- Нет debugger.
- Нет полноценного language server для VS Code.
- Нет formatter и linter.
- Backend пока ориентирован на C99 и GCC/Clang.
- Диагностика покрывает frontend, но не всегда объясняет ошибки C-компилятора.
- Автоматический вывод типов пока намеренно ограничен.

## Каким должен стать полноценный Buff

### Уровень языка

1. **Стабильная типовая система**
   - четкие числовые преобразования;
   - `Option`/`Result`;
   - `enum`;
   - generics;
   - readonly-ссылки;
   - понятные правила nullable и указателей.

2. **Безопасная память по умолчанию**
   - Arena для быстрых временных объектов;
   - ownership для долгоживущих объектов;
   - явные unsafe-блоки для ручных указателей;
   - проверки границ массивов в безопасном режиме.

3. **Нормальные строки и коллекции**
   - `String` с длиной и capacity;
   - `Array`, `Slice`, `Map`, `Set`;
   - UTF-8 API;
   - отсутствие зависимости от `printf` для обычного вывода.

4. **Современная обработка ошибок**

```buff
fn read_config(path: string) -> Result<Config, IoError>
    ...
end
```

Ошибки должны обрабатываться явно, без скрытых `NULL` и неопределенного поведения.

### Уровень компилятора

- отдельный модуль для AST;
- таблица символов с областями видимости;
- полноценный type checker;
- отдельный модуль диагностики;
- оптимизации AST и промежуточного представления;
- dead code elimination;
- постоянные выражения;
- предупреждения о неиспользуемых переменных;
- предупреждения о недостижимом коде;
- стабильный формат ошибок для IDE;
- тесты на каждый этап compiler pipeline.

### Уровень runtime

Runtime должен быть разделен на небольшие модули:

```text
runtime/
    arena.h
    memory.h
    string.h
    array.h
    io.h
    result.h
```

Каждый модуль должен подключаться только при использовании, чтобы маленькая программа не получала огромный runtime.

### Инструменты разработчика

Полноценная установка Buff должна включать:

```text
buff new project
buff build
buff run
buff test
buff fmt
buff check
buff doc
```

Нужны также:

- VS Code extension;
- подсветка синтаксиса;
- автодополнение;
- переход к определению;
- inline diagnostics;
- formatter;
- debugger через native debug symbols;
- profiler;
- кроссплатформенная сборка.

### Package manager

Проект должен иметь manifest:

```toml
[package]
name = "my_game"
version = "0.1.0"

[dependencies]
math = "1.2"
```

Package manager должен фиксировать версии, проверять хеши и собирать зависимости воспроизводимо.

## Философия Buff

Buff не должен пытаться копировать весь C++, Rust или Python. Сильная версия языка должна придерживаться нескольких правил:

1. Синтаксис остается небольшим и читаемым.
2. Ошибки находятся до генерации C.
3. Безопасные операции являются стандартными.
4. Низкоуровневый контроль доступен явно, через `unsafe`.
5. Runtime остается маленьким и быстрым.
6. Инструменты устанавливаются одной командой.
7. Производительность измеряется benchmark-ами, а не обещаниями.
8. Любая сложная возможность добавляется только вместе с понятной моделью типов и диагностики.

## Текущий статус

Buff сейчас лучше всего подходит для:

- изучения устройства компиляторов;
- небольших экспериментов с C backend;
- игровых и системных прототипов;
- проектирования собственного языка;
- проверки идей до создания полноценного toolchain.

Для production-разработки сейчас нужны дополнительные проверки, runtime и инструменты из дорожной карты выше.
